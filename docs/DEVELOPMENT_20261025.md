## 新增实现

- `tools/compare_patient_holdout.py`：重新导出 train 患者留出预测，检查患者列表与 checkpoint 的划分参数相符、不同模型检查/标签/患者顺序一致。拒绝全 train 微调或从比赛 checkpoint 初始化的模型，防止把已见患者当独立留出。不读取 test。
- `tools/patient_statistics.py`：按患者整簇、有放回重采样；所有模型使用相同患者抽样。用患者抽中次数作为其全部检查的权重，计算十类 AUROC、Macro-AUC 与相对参考模型差值的 95% 百分位区间。得分并列按半对计；某轮缺少某类正或负样本时，对全部模型共同剔除此轮，并报告数量。区间仍受 checkpoint/模型选择影响，不宣称是独立确认。
- `tv_densenet121_query`：相同 DenseNet121 骨干接小型疾病查询分类头，256 维、4 头交叉注意力、10 个可学习查询、逐类线性读出；显式 `batch_first=True`。它参考 Query2Label 的一般思想，未宣称完整复现 Query2Label、ML-Decoder 或论文成绩。当前未训练、未加入部署候选，先保留 GAP 分类头完成损失/预热对照。
- `predict.py --validation-only`：仅访问 valid CSV/图像、导出验证指标和可选逐图概率，不生成提交 CSV、不要求 test 存在。`tools/finalize.py` 已改为调用此入口导出候选，方案选定后才执行最终测试推理；真实新包尚未生成。
- `StudyPredictor` 在同一次检查调用内共享原图读取、448 灰度/JPEG 规范化解码，以及相同输入大小/归一化的张量。每次调用仍重新读取文件，不跨检查或跨调用缓存。这样减少集成中的重复解码；实际延迟仍以最终测时为准。
- `src/ensemble.py` 统一固定全局融合权重。除等权外，两模型比较 1:3、3:1，三模型比较 2:1:1 的三个排列。每一组权重同时用于十个类别，不逐类拟合。保存于冻结报告并绑定模型顺序，`predict.py`、`StudyPredictor`、`cost.py` 与选择/打包/核验工具共享相同定义；零、负数、非有限数与数量不符的权重会拒绝。

查询模块不使用独立位置编码：它对 CNN 特征的空间排列不敏感，空间信息来自骨干。分类头内部无跨图像注意力；骨干正常微调时的 BatchNorm 按常规更新，推理时固定为 eval。

## 已通过的检查

在训练环境 PyTorch 2.8 与目标版本 PyTorch 2.10 中均通过：

- 带大量并列分数、患者检查数不等时，加权 AUROC 与 sklearn 的 `sample_weight` 结果误差小于 1e-14。
- 相同模型的患者配对差值区间严格为 [0, 0]；固定种子完全复现；原始划分缺失的类别采用固定排除策略。
- 查询头的 batch/单图结果一致；替换其他图像不改变当前图像结果；空间 token 重排、梯度、严格权重加载、分类头预热期间的骨干参数与 BN 冻结检查通过。这些检查使用合成张量，不是临床数据或泛化成绩。

另在 PyTorch 2.10 通过完整合成部署检查：只有 valid、没有 test 时候选导出可运行，验证概率与完整导出严格相同；同时覆盖旧/新阈值规则、缓存与原图打包复现、模型摘要绑定和仅 test 数据复现。

共享解码在 PyTorch 2.8/2.10 的合成 JPEG 检查中，与成员分别读取预处理的结果严格一致，覆盖 4 种聚合、TTA 开关、混合输入大小/归一化、无正位回退、重复调用及计时图像摘要校验。三个模型对同一检查的每张有效图像只做一次规范化解码，重复调用会再次解码。它不改变预测定义，也不是已实测的新提交包加速结论。

固定权重网格检查使用构造的排序例子，验证非等权能够被选择器检出，未把合成例子的 AUC 当真实模型成绩。PyTorch 2.10 的整包检查另外覆盖两个不同权重模型的 1:3 混合，冻结校准后仅凭 test 数据独立从原图复现，CSV 概率差为 0。原有无权重字段的等权逻辑保留原始求均值算法。

## 有限后台衔接（按更新后的验证指标目标调整）

`tools/finish_research_ablation.py` 默认只打印参数，`--execute` 执行一次有限流程，可用 `--wait-process <明确的训练队列PID>` 等待本机 Windows 队列成功结束。它不会修改、终止其他进程，也不是定时任务。若队列失败、任一训练尚未达到预定轮数/早停条件、checkpoint 与历史不符，立即停止并保留证据。

预定步骤：

1. 原三组的 `best.pt` 继续按固定患者留出保存，完成后与既有 ImageNet ResNet50 做 1000 次患者配对 bootstrap。这部分用于对照报告。
2. **用户将目标更新为“尽可能提升模型在验证集上的指标，然后给出提交文件”。** 另行保存 `official_valid_selected/best.pt`，按官方 valid Macro-AUC 选权重，不替换患者留出 `best.pt`。已运行的第一组由只读 CPU 观察程序提取已落盘的 EMA，后续训练直接保存。保存逻辑会检查一基/零基轮次对应，避免误用 raw 参数或将新指标绑定旧权重。
3. 三组 DenseNet 中按官方验证峰值选一个配方，在全 train 上做最多 6 轮、patience=3 的 384 输入微调，lr=3e-5、seed=2038；不做 Mixup。进入此步后原患者留出不再独立。这是固定微调计划，不宣称分辨率变化已通过单因素验证。
4. 加入已审计的 ImageNet EfficientNetV2-S，增加骨干结构差异：先在全 train 做 320 输入、最多 12 轮、2 轮分类头预热、patience=4、lr=1.5e-4、seed=2039，再做真实 448 输入的最多 6 轮微调、patience=3、lr=3e-5、seed=2040。损失配方沿用获选 DenseNet；官方 valid 选轮次。448 来自原有 448 缓存，未将其冒充更高原始分辨率。
5. 在 PyTorch 2.10 batch=1 重新导出以上候选及已完成 ResNet50 的验证概率。比较最多 3 个模型的子集及上述少量固定全局权重、4 种检查聚合、有/无翻转 TTA，按 Macro-AUC、再 Macro-F1 排名，并在 valid 原图上对实际权重配置筛查耗时。选定后才生成新的 `submission/round2_bundle`，独立读取全部测试原图复现。
6. 冻结模型后，固定随机种子抽取 5 张预热与 100 张测试图，仅检查 cost.py 的三轮结果复现与写出耗时。此结果不触发测试集驱动的模型重选。
