## 新增实现

- `tools/compare_patient_holdout.py`：重新导出 train 患者留出预测，检查患者列表与 checkpoint 的划分参数相符、不同模型检查/标签/患者顺序一致。拒绝全 train 微调或从比赛 checkpoint 初始化的模型，防止把已见患者当独立留出。不读取 test。
- `tools/patient_statistics.py`：按患者整簇、有放回重采样；所有模型使用相同患者抽样。用患者抽中次数作为其全部检查的权重，计算十类 AUROC、Macro-AUC 与相对参考模型差值的 95% 百分位区间。得分并列按半对计；某轮缺少某类正或负样本时，对全部模型共同剔除此轮，并报告数量。区间仍受 checkpoint/模型选择影响，不宣称是独立确认。
- `tv_densenet121_query`：相同 DenseNet121 骨干接小型疾病查询分类头，256 维、4 头交叉注意力、10 个可学习查询、逐类线性读出；显式 `batch_first=True`。它参考 Query2Label 的一般思想，未宣称完整复现 Query2Label、ML-Decoder 或论文成绩。当前未训练、未加入部署候选，先保留 GAP 分类头完成损失/预热对照。
- `predict.py --validation-only`：仅访问 valid CSV/图像、导出验证指标和可选逐图概率，不生成提交 CSV、不要求 test 存在。`tools/finalize.py` 已改为调用此入口导出候选，方案选定后才执行最终测试推理；真实新包尚未生成。
- `StudyPredictor` 在同一次检查调用内共享原图读取、448 灰度/JPEG 规范化解码，以及相同输入大小/归一化的张量。每次调用仍重新读取文件，不跨检查或跨调用缓存。这样减少集成中的重复解码；实际延迟仍以最终测时为准。
- `src/ensemble.py` 统一全局网格和后文的逐类固定融合。全局网格除等权外，两模型比较 1:3、3:1，三模型比较 2:1:1 的三个排列；全局权重同时用于十个类别。权重保存于冻结报告并绑定模型顺序，`predict.py`、`StudyPredictor`、`cost.py` 与选择/打包/核验工具共享相同定义。全局权重必须为正；逐类矩阵允许零系数，每个类别的系数和必须为正；负数、非有限数与形状不符均拒绝。

查询模块不使用独立位置编码：它对 CNN 特征的空间排列不敏感，空间信息来自骨干。分类头内部无跨图像注意力；骨干正常微调时的 BatchNorm 按常规更新，推理时固定为 eval。

## 同骨干权重平均实验

参考 [Model Soups，ICML 2022](https://proceedings.mlr.press/v162/wortsman22a.html) 的权重平均思想，另构造同一 DenseNet121 第 5/6 轮 EMA 的 1:3、1:1、3:1 参数平均，并与两个源模型在相同 PyTorch 2.10 验证路径重新比较。该论文的主要实验证据不来自本胸片比赛，不能先验断言有效；当前是小规模检查点平均实验，不宣称完整复现论文。

`tools/build_weight_soups.py` 不读取图像，不继承父模型指标或训练轮次作为新模型的成绩。浮点参数和浮点缓冲取相同比例的平均，整数 BN 计数取最大值；不重新估计 BN。工具检查架构、输入、状态键/形状/类型与同源通用预训练摘要一致，记录源权重摘要、脚本摘要与工作树状态。输出为一个普通骨干模型，推理模型数量不因此增加；是否保留由重新计算的验证指标决定。

`tools/check_weight_soups.py` 以合成状态验证平均计算、整数处理、不修改父模型、不复制指标，以及不兼容/非有限权重拒绝。五个真实候选均在 Python 3.12 / PyTorch 2.10、CUDA、batch=1、无 TTA、优先正位的同一部署路径重新计算，结果如下。未读取测试图像。

## 患者分组验证的逐类固定融合

对上节相同的三个模型，增加逐类权重，同时将其收缩到全局权重以限制自由度。每个拟合折先从等权与三种 2:1:1 全局比例中选择，再对每类从 1/4 步长的三模型单纯形网格和等权中选择；AUC 平分时取最靠近全局权重者。收缩强度仅比较 0、0.25、0.5、0.75、1，按 2045—2049 五个固定种子的五折患者分组 OOF AUC 均值选择。

| 逐类权重强度 | 五次 OOF Macro-AUC 均值 |
|---:|---:|
| 0（只有全局融合） | 0.798683 |
| 0.25 | 0.800793 |
| **0.5（选中）** | **0.801142** |
| 0.75 | 0.800364 |
| 1 | 0.798349 |

0.5 强度在五次划分中的四次优于同折的全局融合。五次重复使用相同的 228 位患者，并非五个独立样本；此前 CNN 检查点也已按官方验证选择，因此此 OOF 不构成完全独立的模型验证。单个种子 2045 实际偏好强度 0，完整结果保留，未删去不利划分。

按选中强度在完整 valid 重拟合后，通过真实三模型推理重新计算得到 **Macro-AUC 0.806420、调阈值 Macro-F1 0.477395**；与逐个模型导出再融合的结果完全一致。完整 valid 重拟合成绩是偏乐观的模型选择估计，不应与 OOF 混用。强度 1 的重拟合 AUC 虽为 0.809310，但 OOF 较差，未采用。没有读取测试图像或用测试统计量拟合权重。

固定的 3×10 权重、类别顺序和模型 SHA 写入明确的 JSON，并嵌入冻结推理报告。`tools/ensemble_presets.py` 在最终流程中核对源模型、验证 CSV、权重文件摘要及每个新导出的运行配置，重新计算实际 AUC，拒绝缺失成员或与先前证据不符的结果。既有四个单模型候选和这个固定融合均由同一清单显式配置；最终选择前冻结清单字节。

拟合本身可由公开的 `tools/fit_classwise_fusion.py` 复现。该脚本只读取 `valid.csv` 和指定成员的验证导出，严格核对图像顺序、模型/CSV 摘要、batch、TTA 与运行环境；按患者划分拟合权重，保存全部 25 折结果及本地 OOF 数组。AUC 先严格排序，只在完全平分时按全局距离、网格顺序打破平分。已从公开脚本重新运行，五个种子各强度的 AUC、最终权重、患者对齐及第一个重复的实际输出概率均与探索记录完全一致。原始逐例数组不上传仓库。

以下命令使用已验证的 Python 3.12 / PyTorch 2.10 环境，输出目录须不存在：

```powershell
python -m tools.fit_classwise_fusion --checkpoint outputs/soup_baseline_s2036_v2/mix_3/best.pt outputs/soup_cross_warm_s2036/source_2/best.pt outputs/efficientnetv2_b0_s123/best.pt --prediction-files outputs/soup_baseline_s2036_v2/mix_3/validation/predictions.npz outputs/soup_cross_warm_s2036/source_2/validation/predictions.npz outputs/legacy_complementarity_bs1/efficientnetv2_b0_s123/predictions.npz --out outputs/classwise_fit
```

PyTorch 2.10 合成整包检查已覆盖逐类融合、缓存/原图预测、冻结后删除外部权重 JSON、只有 test 数据时独立复现，以及 cost.py 与完整 CSV 的数值一致。合成耗时检查只验证程序一致性，不是官方 5/100/3 测时或 T4 性能证据。真实三模型仍须在最终 valid 原图耗时筛查后才能进入交付包。

另外在 DenseNet 全量训练与其他图形程序同时占用显卡时，对这三个固定模型做了一次真实 valid SSD 原图耗时预检：5 张独立预热、100 个输入、连续 3 轮，batch=1，包含完整检查、固定逐类融合及 CSV 刷新写出，平均 **257.63ms**、P95 **469.24ms**，未通过本机 100ms 限制。该结果属于共享负载下的观察，不能用作空闲性能或 T4 性能结论，也未触发测试集推理或候选淘汰。训练保持运行；最终仍按预定流程在训练结束后统一筛查候选耗时。原始报告和共享负载上下文保存在本地 `outputs/classwise_latency_validation_concurrent*.json`。

针对这次真实负载影响，`tools/finalize.py` 现在默认在每个新的验证耗时配置开始前检查 GPU 0：间隔 2 秒，连续 3 次利用率不高于 20% 才启动测时。高负载会继续等待，不能因此直接跳到较弱候选；不可用或无效的驱动计数会明确报错，完整观察保存为 JSONL，选中耗时报告记录检查结果。该检查只观察资源，不修改其他进程，也不是全程独占显卡或 T4 认证。`--allow-busy-gpu` 是显式绕过入口，本轮衔接流程不使用它。

`tools/check_gpu_idle.py` 检查忙状态重置连续计数、低负载放行、观察落盘、无效/缺失计数拒绝和超时保留候选。当前真实显卡的 100%、86%、100% 三次观察也正确阻止了测时启动，未影响训练。现有衔接程序稍后会启动新的 finalizer 子进程，自动使用这一默认检查，无需中止或重启当前训练。

## 新骨干加入后的有限逐类选择

`tools/automatic_fusion.py` 在全部候选的统一验证导出完成后，对无翻转和翻转 TTA 各选取全局网格中 AUC 最好的三模型及聚合模式，最多进行两次逐类拟合。沿用上文相同的 1/4 单纯形网格、收缩强度 0/0.25/0.5/0.75/1、2045—2049 五次五折患者分组协议。该步骤在新的统一导出之前定义，不读取测试集。TTA、运行环境、模型摘要、验证 CSV 和图像顺序必须与源导出匹配。

交叉验证选择强度 0 时保留已有全局候选；其余情况下把拟合结果加入候选池，与原有全局候选及旧固定逐类候选一起排名。逐类矩阵可为某个模型在某个疾病上赋零权重；对全部十类均为零的模型按精确代数等价移除，减少加载模型数量。拟合前后的模型顺序与摘要、完整 CV 结果和重拟合指标保存于工作目录；冻结推理报告嵌入实际使用的矩阵。此步骤默认启用，可用 `--no-classwise-best-global` 重现仅比较既有候选的选择范围。

图像 checkpoint、三模型组合及聚合模式都已在完整 valid 上选择，因此融合 OOF 仍不是整个流程的独立泛化评估。重复验证选择也会使最终重拟合指标偏乐观；最终报告分别呈现 OOF 和重拟合结果，不称其为隐藏榜单成绩。

`tools/check_automatic_fusion.py` 用构造数据核对每种 TTA 最多拟合一次、选择最高分三模型、固定患者 CV、TTA/模型/类别绑定、全零成员移除后的逐位等价，以及强度 0 回退。另已对原来的三个真实验证导出执行新流程，重新得到 **0.806420**，全部验证指标、最终权重和五次 CV 各强度分数与原固定候选完全一致，没有读取测试输入。原始证据在本地 `outputs/classwise_automatic_actual/`。

新增稀疏系数的整包 CPU 回归覆盖冻结后删除外部权重 JSON、仅 test 数据原图复现、CSV 与 cost.py 一致，以及旧等权/全局加权兼容。首次在旧校准路径生成报告后遇到一次 Windows 原生 `0xC0000005` 退出；日志保留于 `outputs/check_deployment_sparse_20261025.log`，没有把它记为通过或归因到新矩阵计算。限制 CPU 库线程后，完整回归通过；测试脚本现固定此线程配置，其默认命令也已通过。该配置不改变 CUDA 生产路径，最终真实 CUDA 全量复现仍由交付流程完成。
